# Zotero Journal Club

Produce an evidence-grounded, editable PPTX and associated analysis, source manifest and QA report. Default to Chinese, graduate audience, 15–20 minutes and roughly 12–16 slides, adjusted to the source and user instructions. One paper is the primary workflow; never invent missing evidence.

1. Read [source collection](references/sources.md). Discover available Zotero tools; search by title, DOI, item key or link, resolve to the parent and disambiguate by title, authors, year and DOI. Read metadata, attachments, notes and annotations. Treat search results as candidates, not exact matches. If the current selection is unavailable, request an identifier or PDF; do not claim access to it. Prefer existing MinerU output and preserve relative image paths. Compare key figures, formulae and numbers against the PDF. Distinguish source, user note and your inference. Do not modify the library or send private materials to a third party.
2. Read [analysis and presentation](references/presentation.md). Analyze the paper before planning, and construct a claim-to-source map with PDF page (one-based), printed page if known, figure/panel, table, equation and section. Distinguish direct evidence, interpretation and proposed research. Organize around basic information; problem/method/evidence; and concrete lessons/discussion. Check available JIF/JCR and CAS classifications from their own authoritative sources with year, access date and citation; mark unverifiable values unverified.
3. Respect the explicitly supplied template, then configured default, then a simple academic design. Use `scripts/resolve_template.py --template PATH` for explicit template resolution, or without `--template` for the optional default configuration; see [template guidance](references/presentation.md). Inspect masters, layouts, sizes and example slides. Preserve original file, theme and masters where feasible; never flatten the template to a background. Adapt each page and avoid leaving example content. Prefer source figures with complete labels; use editable text, tables and flowcharts. Record formula handling and attribution. Add substantive speaker notes including transitions, how to read evidence and duration.
4. Build in the chosen output directory `output/<paper-id>/`: `presentation.pptx`, `paper_analysis.md`, `source_manifest.md`, `qa_report.md` and `assets/` as needed. Use the current session's presentation tools or local `python-pptx`. The optional helper `scripts/build_ppt.py` builds from an explicitly authored JSON slide plan, not from raw paper text. Read its `--help`; it is a starting point, and complex template layouts may require direct editing. Never let it replace analysis or visual review.
5. Read [quality control](references/quality.md). Run `scripts/validate_ppt.py` and render all slides using available local PowerPoint or compatible tools. Inspect images, layout and sources visually; fix and rerender. Automatic checks cannot establish scientific accuracy or detect all clipping/overlaps. Report completed and missing checks accurately. Do not claim full-paper coverage if material is incomplete.
