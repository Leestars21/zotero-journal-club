# Quality control

Use [visual-quality.md](visual-quality.md) to evaluate visual finish against a supplied/configured reference. Record the reference coverage and representative page comparisons separately from structure/source checks. A repeated bullet-and-thumbnail draft is insufficient when the user has requested a finished academic presentation. Review the actual projected content, fix observed problems, and retain the native/editable PPTX with the visual QA.

Check claims, formula symbols, units, source and notes against the original paper, and verify which of PDF pages and printed pages each locator refers to. Include a claim-to-source ledger for claims, figures, equations and data, with uncertainties and the destination slide. Distinguish JIF, JCR quartiles, CAS divisions, CiteScore and SJR; never substitute one for another.

Reopen the PPTX; check count, editable text, media and notes, then render each slide and examine font size, cropping, readability, overlap and template fidelity. The validator checks package structure, slide boundaries and a text-box overlap heuristic; intentional overlap and inherited formatting can produce false positives or negatives, and a box inside the slide can still contain clipped text. Review warnings visually, fix actual problems, then rerender. In `qa_report.md` record source completeness, tests, fixes and unverified checks; distinguish visual inspection from successful file export. If the renderer is unavailable or content lacks evidence, explicitly report the limit instead of claiming a pass.

For a helper-generated talk, run `validate_ppt.py presentation.pptx --plan slide_plan.json --evidence evidence.json`. It checks actual retained titles/body/columns/notes, native table values, image file hashes, citation labels, source identifiers, PDF page ranges declared in the ledger, and claim destinations. It also rejects paper findings backed only by notes/inference. Without sidecars only the structure and citation-footer heuristic are checked; a visible footer does not prove the cited source supports the slide. Grouped text and native table cells count as editable content. Approximate text fit, small displayed images and low effective image resolution produce warnings that need visual review.

When a workflow or content type changes, exercise it on a real source PDF and an observed template where available. A useful regression case includes original multi-panel images, at least one equation/table, notes or annotations if present, and the full talk's speaking notes. Report an empty annotation result as empty, not as successful annotation integration. Keep private PDFs, caches, complete notes, generated talks and rendering output in the ignored output directory; publish only a concise validation summary with bibliographic sources, the checks performed and material limitations. Existing successful runs are evidence of those inputs, not every paper/template combination.

When a locally installed artifact-tool runtime is available, `scripts/render_preview.mjs` can provide a fallback preview without installing additional software; its positional arguments are the runtime module path, input PPTX, and output directory (see its usage). Inspect every page and label it as an artifact-tool preview, not a PowerPoint-native render. Imported templates, fonts and effects may render differently in the target application. Use the host's Office rendering guidance first when required and record any failures.

On Windows, `scripts/render_powerpoint.ps1 INPUT.pptx OUTPUT.pdf` provides a native PDF export when the available Office helper fails while attempting to hide PowerPoint. It opens the input read-only with no presentation window, avoids setting application visibility, refuses existing outputs, restores automation security and closes only its own presentation. It does not quit an already-running application; an inaccessible running app remains an error. Render the resulting PDF using the host's PDF/Office preview tools and inspect every page. Do not retry unchanged COM failures or modify global Office scripts as part of a paper task.
