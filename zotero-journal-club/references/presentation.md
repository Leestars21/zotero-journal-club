# Analysis and slide design

Extract the research object, existing approaches and specific gap; objective, assumptions, inputs, outputs, theory and method; experimental or computational setup, comparisons, metrics and quantitative evidence. Explain important equations and variables instead of just pasting them. Link each conclusion to precise source evidence and qualify comparison scope. Separate the paper's conclusions from your reasoning. Derive specific lessons about knowledge, research design and transferable methods, plus limitations and testable discussion questions; connect to the user's field only when warranted.

Build a per-slide plan: message, content, figure/equation, locator, duration and layout. Use source figures at sufficient resolution with axes, legend, units and panel labels intact; identify originals, redrawn diagrams and inferences. Cite every reused source and do not substitute generated imagery for results. Editable native objects are preferred for text, tables and flows; preserve difficult original graphics and equations accurately as images if native conversion is unreliable.

Use explicit template, then configured default, then a restrained light academic layout. Review template layouts and sample pages; reuse the actual master/theme and avoid leaving sample content. Theme inheritance is not a guarantee of layout fidelity: inspect the rendered result and refine. Default template may be supplied through the task or local configuration specified by the user. Do not infer a template path. Notes should explain how to present the evidence, transition, assumptions and duration, not merely repeat slide text.

`scripts/resolve_template.py` reads `~/.codex/zotero-journal-club.json` when present; `ZOTERO_JOURNAL_CLUB_CONFIG` or `--config` selects a different file. An explicit `--template` takes priority. A missing configured or explicit file is an error, not permission to ignore the selected template. `scripts/inspect_template.py` lists layouts and placeholders but cannot assess visual fidelity; render and inspect the template as well.

For `build_ppt.py`, use layout placeholders and optional `columns` for two bodies. For a custom layout without placeholders, explicitly choose the observed layout and provide `regions` with title, body, optional body2/image as `[left, top, width, height]` fractions of slide dimensions and appropriate font sizes/colors. Never invent those values without inspecting the template: incorrect positions can obscure its inherited artwork. This mode adds editable text and retains the actual layout; it does not duplicate example slides. Review the result against the source and adjust content and regions if needed.

For an untemplated slide built with the helper, `image_focus: true` gives the image a larger central region; with no bullets it uses more height. Do not assume that this guarantees legibility: inspect axes, legend and panel labels at presentation size. When they remain small, split the explanation across slides or add a clearly identified magnified crop while retaining the complete source figure and attribution.
