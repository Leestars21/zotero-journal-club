# Analysis and slide design

Extract the research object, existing approaches and specific gap; objective, assumptions, inputs, outputs, theory and method; experimental or computational setup, comparisons, metrics and quantitative evidence. Explain important equations and variables instead of just pasting them. Link each conclusion to precise source evidence and qualify comparison scope. Separate the paper's conclusions from your reasoning. Derive specific lessons about knowledge, research design and transferable methods, plus limitations and testable discussion questions; connect to the user's field only when warranted.

Use the reader's notes to prioritize rather than enlarge the talk indiscriminately. For a useful question, locate the relevant passage/figure, decide whether the paper answers it, then place the explanation in a method/result slide or retain it as an unresolved discussion question. Where the user's research context is supported, describe a transferable method, the assumptions required for transfer and a small validation that would test it. These are proposals, not completed results.

Budget time before fixing the slide count. Keep bibliographic background brief and reserve most time for the method, evidence and discussion; adjust to what the paper actually contributes. For a key result figure, speaker notes can name the comparison, experimental/computational conditions, observation, supported conclusion and applicability. For example, a random sample split with the same geometries represented in training may support performance on new geometry–layup combinations; a claim about entirely unseen geometries requires different evidence. Choose clear subject titles for setup slides and supported takeaway titles for result slides.

Build a per-slide plan: message, content, figure/equation, locator, duration and layout. Use source figures at sufficient resolution with axes, legend, units and panel labels intact; identify originals, redrawn diagrams and inferences. Cite every reused source and do not substitute generated imagery for results. Editable native objects are preferred for text, tables and flows; preserve difficult original graphics and equations accurately as images if native conversion is unreliable.

Use explicit template, then configured default, then an intentionally authored academic layout. Read [visual-quality.md](visual-quality.md) and inspect any supplied/configured finished-presentation reference. A quality reference sets visual expectations independently of which template is selected. Review real layouts and sample pages; reuse an actual template's master/theme without leaving sample content. Theme inheritance does not establish fidelity: inspect rendered output and refine. Notes should explain evidence, transitions, assumptions and duration.

`scripts/resolve_template.py` reads `~/.codex/zotero-journal-club.json`; `ZOTERO_JOURNAL_CLUB_CONFIG` or `--config` selects a different file. `--template` takes priority over `default_template`; `--quality-reference` independently overrides `quality_reference`. Missing selected files are errors. A quality reference does not become a build template automatically. `scripts/inspect_template.py --design` also summarizes explicit fonts, sizes, colors and content counts; render the reference to assess fidelity and finish.

For `build_ppt.py`, use layout placeholders and optional `columns` for two bodies. For a custom layout without placeholders, explicitly choose the observed layout and provide `regions` with title, body, optional body2/image as `[left, top, width, height]` fractions of slide dimensions and appropriate font sizes/colors. Never invent those values without inspecting the template: incorrect positions can obscure its inherited artwork. This mode adds editable text and retains the actual layout; it does not duplicate example slides. Review the result against the source and adjust content and regions if needed.

For an untemplated slide built with the helper, `image_focus: true` gives the image a larger central region; with no bullets it uses more height. Do not assume that this guarantees legibility: inspect axes, legend and panel labels at presentation size. When they remain small, split the explanation across slides or add a clearly identified magnified crop while retaining the complete source figure and attribution.

The focused-image helper allocates space for multiple brief text lines and rejects text so dense that the figure would lose its useful area. Move long explanations to notes or a separate page. Native tables explicitly set text/background contrast so inherited white header text cannot disappear on the helper's light table fill; review any custom text color against the chosen background.

Read [slide-plan.md](slide-plan.md) for the helper's research content types and evidence bindings. Use a caption and source IDs for each image when several publications/panels share a page. Native tables must preserve values, units, uncertainty and comparison settings; label excerpts and retain a link to the full source. A reconstructed process diagram is a presenter-authored schematic. Plain-text editable equations suit simple expressions; preserve complex original mathematical notation as a checked source crop when conversion would change it. Put detailed assumptions and reading guidance in notes rather than crowding the projected page.
